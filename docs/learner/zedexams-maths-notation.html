How we write it

One renderer, used everywhere

This is not a games fix. The same component has to serve notes, quizzes, past papers, the study plan, results and the guardian's report — anywhere a fraction can appear. Build it once as <Frac>; the moment two screens render fractions differently, learners notice. In this prototype every fraction on both phones — question, working, answer, reference table — comes out of Frac() and Mixed(). There is no second path.

It has to scale, not just exist

A fraction is sized in em, not px, so it grows with the sentence around it and still sits on the baseline. The reference phone prints the same fraction inside body text, a list row and an exam-zoom heading — if it only worked at one size it would be obvious there.

The pad has to match the question

A child cannot answer a stacked fraction in one text box. Two boxes and a bar, a whole-number box in front when a mixed number is on the table, and the same number pad used everywhere else. Tap a box to move focus; the numerator auto-advances at two digits.

Marking lives in one function, not per question

markFractionAnswer() is the only thing that decides. Its rules: an unsimplified but correct answer is right, with a follow-up line naming the simpler form; improper and mixed are interchangeable; a decimal is refused for a fraction question unless the question says otherwise. Switch the rig to lowest terms and the identical answer flips to wrong — the change is in the question's data, not in new code.

Signs matter too

ECZ papers use ÷ × −, not / * -, and Zambian money is written K180.00. The minus is U+2212, not a hyphen — a hyphen is narrower and sits lower, and in a column of subtractions it reads as a typo.

Read-aloud is the accessibility test

Every fraction carries role="math" and an aria-label in words, with the digits hidden from the accessibility tree so nothing says "three four". The read-aloud button speaks that same label — one string for the screen reader and the paid voice, so they cannot drift apart.

Migration is a report, not a rewrite

The scan below is deliberately timid. It converts only what is unambiguously a fraction and prints everything else for a human — dates, km/h, and/or, ratios. Converting those blindly is how "3/4 of the class" and "12/03/2026" end up rendered the same way.
