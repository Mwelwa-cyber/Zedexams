# AGENTS.md: ZedExams Android Developer Guide

This Capacitor-based hybrid Android app ships a web app via WebView with minimal native code. Understanding the architecture, build system conventions, and deployment pipeline is critical for productive AI-assisted development.

## Quick Reference for AI Agents

**Immediate Do's & Don'ts**:
- ✅ Use Capacitor plugins for native features (e.g., `@capacitor/camera`, `@capacitor-community/*`)
- ❌ Never write Java code; edit only TypeScript/Kotlin in Capacitor plugins
- ✅ Update dependency versions in `variables.gradle` (single source of truth)
- ❌ Never hand-edit `app/capacitor.build.gradle` or `capacitor.settings.gradle`
- ✅ Run `./gradlew assembleDebug` (or `gradlew.bat` on Windows) for local builds
- ✅ Always set `ZED_VERSION_CODE` for release builds (env var, not git history)

**Most Common Tasks**:
| Task | Action |
|------|--------|
| Add dependency | Edit `variables.gradle`, then reference in `app/build.gradle` |
| Debug locally | `./gradlew assembleDebug` → emulator or device |
| Build release | Set 4 env vars (`ZED_RELEASE_*`) + `./gradlew assembleRelease` |
| Add Capacitor plugin | Install via npm, run `npx capacitor sync android` |
| Fix build error | Check `gradle.properties` JVM args or run `./gradlew clean` |
| StatusBar icon color wrong | Icons adapt to content brightness in JS (`src/utils/statusBarManager.js`). Force a colour under the bar with `data-statusbar="light"`/`"dark"` on the element; tune thresholds in `statusBarBrightness.js` |
| Android 15+ edge-case | Edge-to-edge is embraced, never opted out of: `EdgeToEdge.enable(this)` in `MainActivity` + safe-area insets in CSS. Do NOT add `android:windowOptOutEdgeToEdgeEnforcement` (or `statusBarColor`/`navigationBarColor`) to the theme — those are the deprecated parameters Play Console flags |

## Architecture Overview

**Capacitor Bridge Model**: The app is primarily JavaScript/web-based, running in an enhanced WebView with native Android bindings. `MainActivity.java` extends `BridgeActivity` — it installs a splash screen and delegates everything to the Capacitor framework. Do not add Java code; instead, use Capacitor plugins or TypeScript/JavaScript.

**Multi-Module Gradle Project**:
- `:app` — Main APK/AAB, UI theme, AndroidManifest.xml, resources (drawables, strings, styles)
- `:capacitor-cordova-android-plugins` — Bridge between Cordova plugins and Capacitor (locally generated; don't edit)
- `:capacitor-android`, `:capacitor-app`, … — Capacitor framework and plugins (from `node_modules/@capacitor/android/`, auto-wired by `capacitor update`). NOTE: `@capacitor/status-bar` is deliberately NOT installed — its Android class carries the `Window` APIs Android 15 deprecated for edge-to-edge (`setStatusBarColor` etc.), which trips the Play Console "deprecated APIs for edge-to-edge" warning; status-bar icon styling goes through `@capacitor/core`'s built-in SystemBars plugin instead

**Key Files Not to Edit**:
- `app/capacitor.build.gradle` — Generated by `capacitor update`; Java version and dependency injection happens here
- `capacitor.settings.gradle` — Generated by `capacitor update`; wires Capacitor modules into Gradle
- Do not hand-edit these; run `capacitor update` after changes to `capacitor.config.json` instead

## Build System & Version Management

**Version Code Strategy** (prevents "won't install newer version" Android failures):
1. If `ZED_VERSION_CODE` env var set, use it (CI uses this)
2. Otherwise, derive from git commit count: `git rev-list --count HEAD`
3. Fallback to hardcoded `3` for shallow/tarball builds

Set `ZED_VERSION_CODE` in CI/CD; do not rely solely on git history for production builds.

**Release Signing** (all-or-nothing validation):
Requires ALL four env vars, or unsigned APK is produced (Play Store rejects). Print warning on build.gradle read makes failure obvious:
- `ZED_RELEASE_STORE_FILE` — Path to keystore
- `ZED_RELEASE_STORE_PASSWORD` — Keystore password
- `ZED_RELEASE_KEY_ALIAS` — Key alias in keystore
- `ZED_RELEASE_KEY_PASSWORD` — Key password

If building release without full config, build succeeds but warns "produce unsigned APK."

**Gradle Wrapper**:
- Gradle 9.1.0, Android Gradle Plugin 9.0.1 (see `android/gradle.properties` for the
  `android.newDsl` / `android.r8.strictFullModeForKeepRules` compatibility flags this
  upgrade needed, and `android.enableR8.fullMode=false` — still off, independent of the
  AGP version — for why R8 stays in compatibility mode)
- Always use `./gradlew` (or `gradlew.bat` on Windows) to ensure CI/local consistency
- JVM args: `-Xmx1536m` (gradle.properties); allows parallel builds if needed

**Centralized Dependency Versions** (`variables.gradle`):
All dependency versions declared once in `ext { ... }` block. Update there, not inline in `app/build.gradle`. Example:
```groovy
androidxAppCompatVersion = '1.7.0'
// then in app/build.gradle:
implementation "androidx.appcompat:appcompat:$androidxAppCompatVersion"
```

## Android Version & Feature Constraints

- **Min SDK**: 24 (Android 7.0) — see `variables.gradle`
- **Target/Compile SDK**: 36 — see `variables.gradle`
- **Named Namespacing**: `namespace "com.zedexams.android"` in `app/build.gradle`

**Android 15/16 edge-to-edge** — embraced, never opted out of:
- `MainActivity` calls `EdgeToEdge.enable(this)`; the system bars are fully transparent and the WebView draws behind them. `@capacitor-community/safe-area` bridges the real bar insets into CSS `env(safe-area-inset-*)` so content stays clear of the bars.
- `styles.xml` deliberately sets **no** `statusBarColor` / `navigationBarColor` / `windowOptOutEdgeToEdgeEnforcement` — those theme parameters (and the matching `Window` setters) are deprecated in Android 15, and their presence is what trips the Play Console "deprecated APIs or parameters for edge-to-edge" warning.
- **Status-bar icon appearance** (light vs dark icons) is owned by `@capacitor/core`'s built-in **SystemBars** plugin via `SystemBars.setStyle()` in `src/utils/statusBarManager.js` (routes through `WindowInsetsControllerCompat`, not deprecated). The legacy `@capacitor/status-bar` plugin was removed for exactly this reason (its DEX carries `Window.setStatusBarColor` and friends even when never called) — do not re-add it.
- **A Play Console "deprecated APIs for edge-to-edge" warning naming `androidx.activity.*` (obfuscated names like `d0.c`/`x.c`/`y.c`/`z.b`, never a class under `com.zedexams.android`) is androidx.activity's OWN pre-API-30 compat shim, not an app bug.** `EdgeToEdge.enable()` still calls `Window.setStatusBarColor`/`setNavigationBarColor` and sets `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES` internally on devices below the API level where `WindowInsetsController` exists (30) — there is no other public API to draw a status/nav-bar scrim on Android 7–9, which `minSdkVersion = 24` still supports. This is tracked upstream and unresolved as of androidx.activity 1.13.0 (see [flutter/flutter#183349](https://github.com/flutter/flutter/issues/183349), [dotnet/maui#26788](https://github.com/dotnet/maui/issues/26788), [material-components-android#4732](https://github.com/material-components/material-components-android/issues/4732)); it disappears only when AndroidX ships a fix, or if this app ever raises `minSdkVersion` past that floor — a product tradeoff over budget-device support, not something to change here on your own. Keep `androidxActivityVersion` (+ `androidxCoreVersion`/`androidxAppCompatVersion`, which it resolves closely against) current in `variables.gradle` so a future upstream fix is picked up automatically; do **not** attempt to work around it by re-adding manual `setStatusBarColor`/`setNavigationBarColor` calls or a `windowLayoutInDisplayCutoutMode` override — that would add a *second*, app-owned instance of the same deprecated call on top of the library's.

## Build Artifacts & Asset Flow

**Web Assets**:
- Generated assets (`app/src/main/assets/public/*`, `capacitor.config.json`, `capacitor.plugins.json`) are git-ignored and built by the web layer
- `capacitor update` copies them after web build
- Release builds run R8 (`minifyEnabled = true` + `shrinkResources`) over the native class graph; the web bundle is minified separately by Vite. Keep rules: consumer rules merged from dependency AARs (Capacitor ships the plugin-reflection keeps) plus `app/proguard-rules.pro`

**Asset Configuration** (`AndroidManifest.xml` + `aaptOptions`):
```xml
ignoreAssetsPattern '!.svn:!.git:!.ds_store:!*.scc:.*:!CVS:!thumbs.db:!picasa.ini:!*~'
```
Allows dot-files for modern web apps (`.well-known/`, `.htaccess`).

**Resources** (`res/`):
- Per-DPI drawables: `drawable-{hdpi,mdpi,xhdpi,xxhdpi,xxxhdpi}` and landscape variants
- Strings/colors centralized in `res/values/strings.xml` and `res/values/ic_launcher_background.xml`
- URL scheme: `com.zedexams.app` (for deep linking, if used)

## Commands & Workflows

**Clean Build** (wipe generated files):
```bash
./gradlew clean
```

**Debug APK** (development, local testing):
```bash
./gradlew assembleDebug
# Output: app/build/outputs/apk/debug/app-debug.apk
```

**Release APK** (with signing):
```bash
export ZED_VERSION_CODE=100 ZED_VERSION_NAME="1.1.1"
export ZED_RELEASE_STORE_FILE=/path/to/keystore ZED_RELEASE_STORE_PASSWORD=pwd \
  ZED_RELEASE_KEY_ALIAS=alias ZED_RELEASE_KEY_PASSWORD=keypwd
./gradlew assembleRelease
# Output: app/build/outputs/apk/release/app-release.apk
```

**Bundle for Play Store** (AAB):
```bash
./gradlew bundleRelease
# Output: app/build/outputs/bundle/release/app-release.aab
```

**Build with Capacitor Integration** (after web app rebuild):
```bash
# From project root (not this android/ dir):
npx capacitor sync android
cd android && ./gradlew assembleDebug
```
Syncs web assets and regenerates Capacitor glue code.

## Project-Specific Conventions

1. **No Custom Java Code** — Use Capacitor plugins instead. If feature requires native, check capcitor.dev first; contribute upstream if absent.

2. **Theme Override Pattern** — Theme variants handle launch (with splash) vs. running UI:
   - `AppTheme.NoActionBarLaunch` (launch with splash)
   - `AppTheme.NoActionBar` (running app, system bar colors)
   - `postSplashScreenTheme` attribute hands off once splash dismisses

3. **Version Code Monotonicity** — Build system guarantees every commit → unique APK version, avoiding Android installer rejection.

4. **Environment-Driven Configuration** — No hardcoded secrets; all signing and versioning driven by env vars (CI sets these; local dev omits for unsigned builds).

5. **FileProvider for URI Sharing** (AndroidManifest.xml) — Handles deep links and file picks via `androidx.core.content.FileProvider`; configuration in `res/xml/file_paths.xml`.

## Troubleshooting & Common Gotchas

- **"version code unchanged" error**: Check env var `ZED_VERSION_CODE` is set to higher number; git count fallback requires clean repo.
- **Status-bar icons wrong on cold start**: the adaptive icon manager (`src/utils/statusBarManager.js`) commits its first decision on init; the bars themselves are transparent (edge-to-edge) and no background colour is ever set natively.
- **Capacitor plugins not found after `capacitor.config.json` edit**: Run `capacitor sync android` to regenerate `capacitor.build.gradle` and `capacitor.settings.gradle`.
- **"google-services.json not found" warning**: Normal if Firebase not enabled; plugin only applied if file exists and has content.
- **Release crash traces look garbled**: R8 minifies release builds (`minifyEnabled = true`). Retrace with the mapping file from `app/build/outputs/mapping/release/mapping.txt` (upload it to Play Console with each release). A plugin breaking only in release builds usually means a missing keep rule — add it to `app/proguard-rules.pro`.

## Capacitor Plugin Integration Pattern

**Adding a New Plugin** (e.g., push notifications, file system access):

1. **Install from web root** (not android/):
   ```bash
   npm install @capacitor/push-notifications
   ```

2. **Sync Android native code**:
   ```bash
   npx capacitor sync android
   ```
   This regenerates `capacitor.build.gradle`, `capacitor.settings.gradle`, and plugin configs.

3. **Update AndroidManifest.xml** if plugin needs permissions (e.g., `<uses-permission android:name="android.permission.PUSH_MESSAGING">`).

4. **Call from TypeScript/JavaScript**: Capacitor plugins expose a Bridge API:
   ```javascript
   import { PushNotifications } from '@capacitor/push-notifications';
   const result = await PushNotifications.requestPermissions();
   ```

5. **Avoid**: Never modify plugin source in `node_modules/` or `:capacitor-*` modules directly; contribute upstream instead.

## Web-to-Native Communication Flow

```
TypeScript/JavaScript (WebView)
    ↓ (Capacitor Bridge)
MainActivity.invoke(pluginName, method, args)
    ↓ (Plugin Handler)
Native Android Code (Java/Kotlin)
    ↓ (Promise callback)
JavaScript Promise.resolve(result)
```

**Example**: App calls JS → Capacitor serializes to JSON → Plugin listener → callback fires in JS.
**Keys**: All communication is async (Promise-based); no blocking I/O.

## AI Agent Decision Tree

**"How do I add feature X?"**

- **Is it Web-only?** (UI, styling, logic)
  → Edit in web layer; `npx capacitor sync android && ./gradlew assembleDebug`

- **Does it need OS access?** (camera, files, notifications, sensors)
  → Check https://capacitorjs.com/docs/plugins for existing plugin
  → If exists: `npm install @capacitor/X && npx capacitor sync android`
  → If absent: Build custom plugin (or use Cordova bridge if available)

- **Is it Android-specific?** (deep OS integration)
  → Contribute to Capacitor upstream or community plugin
  → Test in `:capacitor-android` module for compatibility

- **Does it need build-time config?**
  → Edit `app/build.gradle` (AndroidManifest, resources) or `variables.gradle` (versions)
  → Rerun `./gradlew clean assembleDebug`

- **Does it involve UI theme/styling?**
  → Edit `res/values/styles.xml` (Android theme)
  → Edit web layer CSS
  → Both must stay in sync; test both launch (splash) + running (dark/light) states

- **Build or runtime error?** Checklist:
  1. Is `ZED_VERSION_CODE` set? (for release only)
  2. Are all 4 `ZED_RELEASE_*` env vars present? (for signing only)
  3. Run `./gradlew clean` to wipe stale build artifacts
  4. Check `gradle.properties` JVM args: `-Xmx1536m`
  5. Did you forget to run `npx capacitor sync android` after editing `capacitor.config.json`?
  6. Is `google-services.json` missing? (OK if Firebase not used; plugin gracefully skips)
